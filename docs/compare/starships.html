Two Lite starships, one rhythm apart

The two FSR 4.1.2 Lite builds of this project, drawn as starship engineering displays. One cycle is one game frame. The frame enters at the sensor array (the prepass), passes through three plasma injectors (the network's three passes) and the image assembly (the postpass), and appears on the viewscreen; the image assembly also keeps a copy in the log buffer as history for the next frame.

Same picture as AMD's Lite

4.1.2l-exact

All three injectors fire on every cycle, as in AMD's own Lite. The reference panel compares each frame with AMD's: the deviation stays at zero, because the output is the same, byte for byte. The ship is tuned finer, so each cycle costs less.

  • Sensor array: the prepass gathers the frame's color, depth and motion
  • Injectors 1-3: the network's three passes, AMD's weights
  • Image assembly: the postpass builds the picture
  • Log buffer: history for the next frame
  • AMD reference: AMD's Lite, for comparison
4-17%less time per frame than AMD's Lite, Windows timing-kit reports
Changes the picture

4.1.2l-lossy

The injectors fire on every other cycle. On the cycles between they stand by: the pattern buffer holds the last network output, and course correction moves it along the game's motion before the image assembly uses it. Its weights were retrained for this rhythm, so the cycles run faster.

  • Sensor array: the prepass, every frame
  • Injectors 1-3: the network, every other frame, retrained weights
  • Pattern buffer: the stored network output
  • Course correction: moves it with the motion
  • Image assembly: the postpass, every frame
12-25%less time per frame than AMD's Lite, Windows timing-kit reports
