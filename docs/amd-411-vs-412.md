# AMD's FSR 4.1.2 against 4.1.1: what actually differs

Many people expect FSR 4.1.2 to look better than 4.1.1. What it changes depends on the graphics chip, and on Radeon RX 7000 and RX 6000
cards the picture in games is the same. This page sums up what this project found by examining AMD's FSR 4.1.2. It first came inside AMD's
graphics driver (Adrenalin 26.10.1, October 20, 2026); since October 28, 2026 it is also the game DLL of AMD's FSR SDK 2.4.0
(`amd_fidelityfx_upscaler_dx12.dll` version 4.1.2.4555). The two carry the same FSR 4 shaders, byte for byte. Games released before
that ship 4.1.1 (version 4.1.1.2740) or older.

**How the picture is judged here:** by recorded game clips (Shadow of the Tomb Raider, Black Myth: Wukong Benchmark Tool), each run
through both versions with the game's own inputs. Synthetic test scenes can show differences no game shows; where they do, it is said so.
AMD's 4.1.2 shaders were run in this project's local test harness, not in AMD's own runtime.

| Your graphics chip | What AMD's 4.1.2 uses | Picture against 4.1.1 | Speed against 4.1.1 |
|---|---|---|---|
| Radeon RX 7000 (RDNA 3) | the same network with the same weights, compiled slightly differently | **identical, byte for byte** | about the same or a little slower (AMD's 4.1.2 DLL under Linux on an RX 7800 XT: 4% slower at 4K, 2% at 1080p; Windows: being measured) |
| Radeon RX 6000 (RDNA2) | the same network with the same weights; its first and last shaders rebuilt for RX 6000 | **the same in games:** it differs only in rounding; in recorded game clips no difference could be measured | **faster** on RX 6000 cards under Windows: 4 to 21% at 4K (one report 29%), 6 to 16% at 1080p (timing-kit reports) |
| Graphics built into the processor (Ryzen AI and other APUs) | most likely **FSR 4.1.2 Lite**, a smaller network with its own weights (not confirmed which model the driver picks on which chip) | **different:** a smaller network, a different picture | much faster: about 59% less time than 4.1.1 at 4K (Linux, RX 7800 XT) |
| Radeon RX 9000 (RDNA4) | its FP8 version | not examined | not examined |

## Radeon RX 7000

AMD's FSR 4.1.2 for RX 7000 runs FSR 4.1.1's network with the same weights. Its shaders differ from 4.1.1's in two small ways: the last
shader puts the constant operand of its dot products second, and the network's shaders convert their rounded outputs straight to 32-bit
integers. **The output is the same as 4.1.1's, byte for byte** (this project's test rig, 48 comparisons over four output sizes, still
and moving scenes, the game's auto exposure off and on; AMD's 4.1.2 SDK DLL gives the same frames as 4.1.1 on the rig too). Speed of
AMD's 4.1.2 DLL under Linux on an RX 7800 XT, moving scene: 4.98 against 4.78 ms for 4.1.1 at 4K (4% slower), 2.20 against 2.19 ms at
1440p, 1.05 against 1.04 ms at 1080p; its shaders run in this project's test harness time the same within 0.5%. Windows figures will come
from the timing kit.

## Radeon RX 6000

AMD's FSR 4.1.2 for RX 6000 also runs 4.1.1's network with the same weights. Its first shader (which prepares the network's input) is
rebuilt in a layout that suits RX 6000 chips and sums its values in another order; the last shader computes its sample positions in
another order; and network pass 11 is written out in full. The changed order of the arithmetic means a few values round differently:

- **In recorded game clips no difference could be measured.** Its output was 54 to 56 dB from 4.1.1's on four clips (on average well
  under one step of 255 per pixel), and frame-to-frame change and speck counts were within about 1% of 4.1.1's.
- On synthetic test scenes it showed fewer bright rain specks than 4.1.1 (1,048 against 1,314 with the game's auto exposure off, 2,353
  against 3,764 with it on) and slightly less ghosting. Other orders of the same arithmetic gave similar counts, and none of it showed in
  the game clips.

It is **faster on RX 6000 cards.** Timing-kit reports under Windows, its shaders against 4.1.1's on the same card, moving scene:

| Card | 1080p | 1440p | 4K |
|---|---|---|---|
| RX 6950 XT | 7% | 11% | 21% |
| RX 6800 XT | 6% | 11% | 18% |
| RX 6800 | 6% | 6% | 9% |
| RX 6750 XT | 6% | 9% | 10% |
| RX 6700 XT | 6% (one report 12%) | 7% (one report 27%) | 8% (one report 29%) |
| RX 6700 | 6% | 7% | 6% |
| RX 6650 XT | 12% | 15% | 18% |
| RX 6600 XT | 15% | 8% | 6% |
| RX 6600 | 9 to 16% | 11 to 17% | 4 to 17% |

Several reports per card where a range is given; the spread is mostly the card and its setup.

## Graphics built into the processor

For Ryzen AI and other APUs, AMD's driver adds **FSR 4.1.2 Lite**, a smaller FSR 4 network with its own weights. Which model the driver
uses on which chip is not confirmed; Lite is the likely one. Lite is a different network, so its picture is different: a little less
accurate on still pictures, better on some motion, worse on other motion. How it compares with 4.1.1 and other upscalers:
[upscaler comparison](upscaler-comparison.md), with recorded game clips on the
[comparison site](https://zgauthier2000.github.io/fsr4-upscaler-compare/). It is much faster: under Linux on an RX 7800 XT, 2.02 ms against
4.92 ms for 4.1.1 at 4K.

## Where this project's builds stand

- **exact, RX 7000 / RDNA 3 / other cards:** FSR 4.1.1's picture, which is also AMD's FSR 4.1.2 for RX 7000's picture, byte for byte.
- **exact, RX 6000 / Steam Deck / older built-in graphics:** AMD's FSR 4.1.2 for RX 6000's picture, byte for byte (since `dll-NEXTVER`).
- **4.1.2l-exact:** AMD's FSR 4.1.2 Lite's picture, byte for byte.
- How much faster each is than AMD's own FSR 4.1.2 on a given card is what the timing kit's next version measures: it times AMD's
  FSR 4.1.2 shaders for RX 6000 and RX 7000 on every card and reports them against 4.1.1 and against this project's builds.

## Not checked

RX 9000 (RDNA4, FP8). Which model AMD's 4.1.2 uses on each built-in graphics chip (the SDK's notes list Strix Point, Gorgon Point and Ryzen
Z2 chips for the small model). The RX 6000 and Lite timings above are of AMD's 4.1.2 shaders in this project's local test harness; the
RX 7000 figures are of AMD's 4.1.2 DLL itself, which the harness matched within 0.5%.
